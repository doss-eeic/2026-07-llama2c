# 小さいdiffで採用する最適化戦略（2026-10-22）

結論は「OpenMPのQKV・FFN融合を本体にし、CPU配置と分配の選択は外部に置く」。既存測定からの採用判断であり、新しい組合せの速度を保証するものではない。

## 採用する構成

- 本体はe02948e2の融合。QKVの3並列区間を1つにし、FFN up/gateとSwiGLUを1つにする。重み再配置・追加の重みコピーは不要。各内積の累積順を保持する。
- 当面は層内とoutputを同人数にする。P4E4固定とP2E8固定など、既に結果のある構成を使う。scheduleとoutput設定を必ず明示する。
- CPUのSMT/L2構造は外部Pythonで候補を作るために使う。推論ループに予測器や毎tokenの再探索を入れない。外部探索のコード量まで含めれば小さいdiffではないため、用途がこの機体だけなら保存済み設定を選ぶだけでよい。
- 研究としては「並列区間の融合」と「異種コアの人数・配置・分配との相互作用」を主題にする。QKV/FFN個別比較も既存結果がある。強い相乗効果やモデル探索の一般優位は主張しない。

## 実際の差分規模

基準は未改造350e04feのrun.c。git diff --numstatで計測し、実験ログ・文書・テスト・Pythonは除外。

## 設定例の扱い

既存の主測定で速かったP2E8_dynamicは、CPU=(0,2,4,5,6,7,8,9,10,11)、10人固定、通常dynamic,16、output dynamic,128。最新独立確認のqkv-ffn参照はP4E4、通常dynamic,16、output dynamic,32。別フェーズの744.31と772.81を比較して採用順位を決めない。
