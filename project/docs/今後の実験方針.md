# CPU-Profilerの今後の実験方針（2026-10-20）

> この文書は`1fa118a`時点の検討記録。`e78d28e`でQKV/FFN融合の結果が追加された。
> 最新の実験設計は[並列化の切り出しと実測選択](parallel-experiment-design.md)を参照。

調査対象：`project/プロジェクトReadMe.md`、`project/docs/AI用のメモ.md`、
`dev/wataru-2`の`AI用のメモ2.md`・stay2調査、現在の通常・詳細ベンチマーク。
現ブランチは`1fa118a`、旧ブランチは`0900c3d`を確認した。
新たなLinux性能測定は実施していない。

## 推奨する方向

元の「CPUトポロジーを調べ、実測で構成を選んで以後利用する」という目的に戻る。
最初の成果は、未改造の本家について良い固定CPU構成を選択できること。
演算別切替と不均等分割は、固定構成を上回ることを確認してから追加する。
stayやP:E=2:1を採用すること自体を目標にはしない。

研究上の問いは「SMT・Eクラスタ配置・演算形状を利用した構成選択が、
最良の固定構成に対し、切替費用込みでいつ有利になるか」とする。

## 証拠の整理

| 観察 | 根拠と範囲 | 判断 |
|---|---|---|
| スレッド数だけで性能は決まらない | AI用メモのE4単一クラスタ対2+2配置で約1.4〜1.5倍差。異なる実験でも観察 | 候補生成にL2共有関係を使う根拠は強い |
| 演算で有利な構成が異なる | AI用メモのE4/E6、旧メモ2のP4/P4X4、今回のQKV/FFNの差 | 演算別最適化の動機は残る |
| L2容量競合が原因である | ミス・帯域等の直接測定は未確認。A/B非対称もある | 原因としては未確定 |
| P4のSMTは有効 | 過去メモではP2からP4_HTで約1.45倍 | P2とP4_HTを固定候補として残す。全モデルでの保証ではない |
| outputはP側に多く割り当てるべき | 旧stay2では有効、現在のstayでは逆転 | 固定比率を一般則にしない |
| stayはOpenMPより速い | 現在のP4比較は測定間で逆転、P4E4では本家が優位 | 採用根拠はまだない |

メモに記載された古い数値のうち、対応する生ログを現ブランチで再確認できないものは、
再集計したデータと区別し、過去の観察として扱う。

## 旧stay2と現在の違い

旧結果：[probe_stay2_20261020_133855_042738/comparison.csv](https://github.com/doss-eeic/2026-07-llama2c/blob/0900c3d/results/probe_stay2_20261020_133855_042738/comparison.csv)。
現在：`results/stay_detail_20261020_155033_512133/summary.csv`。

| 構成 | 旧forward中央値 ms | 現在forward中央値 ms |
|---|---:|---:|
| P4固定 | 1.785 | 1.579 |
| P4E4固定 | 3.310 | 1.460 |
| 均等切替 | 2.149 | 1.450 |
| 重み2切替 | 1.704 | 1.523 |

旧はTIMING_ONLYの固定入力replay、現在は詳細計測ありの生成。絶対時間の変化を
実装の改善率と解釈しない。入力222トークンは現在の60試行すべてで旧replayと一致。
モデル形状も一致するが、モデルファイルの内容一致は形状だけでは保証できない。

旧と現在では、GEMVの呼び出し構造、Attentionのhead配分、coordinatorの配置、
計測用バリアが異なる。旧詳細版は各stageに追加バリアがある。
同じ固定プールという設計でも、同一実装の比較ではない。

OpenMP詳細計測ソース`run_detail.c`は旧ブランチと完全一致した。
それでも旧`20261019_175702`のP4X4は1.855ms、現在の10回平均は1.380ms。
旧は単発なので厳密な改善率ではないが、stay以外にも速度の変化がある。
コンパイラ・バイナリ・モデルハッシュ・電源状態等を含めて比較する必要がある。

## 現在の改善余地

詳細集計の10試行平均（`results/stay_detail_20261020_155033_512133/aggregate.csv`）。

| 構成 | 層内 ms | output ms | forward ms |
|---|---:|---:|---:|
| 本家P4_HT・計測版 | 0.844 | 0.770 | 1.615 |
| 本家P4E4・計測版 | 0.836 | 0.542 | 1.380 |
| stay P4固定 | 0.792 | 0.785 | 1.585 |
| stay P4E4固定 | 0.903 | 0.553 | 1.493 |
| stay均等切替 | 0.850 | 0.544 | 1.439 |
| stay重み2切替 | 0.868 | 0.627 | 1.529 |

現在の本家P4E4では、outputは約39%、層内は約61%。旧メモ2のP4基準の
output約47%という割合を、現在の最速構成へそのまま適用しない。

別条件の良い部分を組み合わせ、stay P4層内0.792 + 本家P4E4 output0.542とすると
1.334ms。比較対象1.380msとの差は約0.045ms（約3.3%）しかない。
これは実現可能性を保証しない楽観的な見積もりで、dispatch等の費用も含まない。
現状では、切替実装に大きな複雑さを加える前にこの余地の再確認が必要。

同じOpenMP内でもQKVはP4が約0.037ms、AttentionはP4が約0.023ms速い一方、
FFN行列積合計はP4E4が約0.066ms速い。演算別の有利不利は残っているが、
各演算で切り替えると呼出頻度と同期費用が増える。

## 次の実験の順序

### 1. 旧結果の順位逆転を、同時比較で調べる

旧stay2と現在のstayで、P4固定・P4E4固定・均等切替・重み2切替の4条件を用意する。
同じコンパイラ・最適化・モデル・固定入力・skip範囲で、詳細時計を止めた
forward全体を測る。本家P4_HT/P4E4も同一ブロックへ含める。
全候補を1回ずつ実行するブロックを反復し、ブロック内の順序をランダム化する。
現在の「全試行を一括シャッフル」と区別する。
各条件の測定外ウォームアップを揃え、別セッションでも再現を確認する。

主比較は実運用の電源設定を保ち、設定と利用可能な温度・周波数情報を保存する。
実行CPU・ワーカーCPU時間・起床時間・PMU等の診断は別走行にする。
実装差と環境差を一度に帰属せず、旧実装だけで逆転するか、両方で逆転するかを見る。

### 2. 少数の固定候補を選ぶCPU-Profilerを先に完成させる

本家の同一バイナリで、P2、P4_HT、P4_HT+E2、P4_HT+E4等を比較する。
E追加時は同一クラスタとクラスタ間分散を含める。E2は1+1と2+0を比較し、
E4は2+2と4+0を比較する。過去メモでは2スレッドの分散が逆効果だったため、
常に均等分散すれば良いとは仮定しない。必要ならA/Bを反転する。
LP Eは最初の探索から分け、CPU番号はトポロジーから対応づける。

モデル・実装・CPU構成に対する推奨設定を保存し、以後の起動に再利用する。
勝者の確認は探索に使っていない別試行で行う。数%の差が安定しない場合は、
より単純な構成を選び、唯一の最速と断定しない。

### 3. 同じstay実装内で、output配分だけを調整する

手順1で分業の利益が再現した場合に進む。CPU集合・層内チーム・待機方式を固定し、
outputのP:Eを1:2、1:1、3:2、2:1等の少数候補で比較する。
P側4人は2物理PコアのSMTなので、単一P/Eコアの性能比をそのまま行数比にしない。
全体forwardで比率を選び、別試行で最良の固定構成に勝つかを確認する。
単体GEMVだけで比率を確定しない。

### 4. 効果が残る場合だけ、演算群・モデルへ拡張する

QKV、FFN、outputのような演算群から始め、層別・演算別すべての直積探索は後回し。
次に別モデルと短い/長いコンテキストで確認し、stories15Mの288次元・6headsに
特有の結果と一般性を分ける。設定は起動時の校正で選び、毎トークンの探索は避ける。
SIMD・量子化・内積順序の変更は、配置と配分の効果を確認した後の別実験にする。

## 採用判断

採用対象は「そのセッションで最良の本家固定構成」を、切替・同期込みで
繰り返し上回る設定。P4だけを比較対象にして改善と判定しない。
詳細ログは原因の診断、タイマーを止めた全体forwardは採用判断に使う。
生成全体のtokens/sは別指標として併記し、forwardの逆数と混同しない。
