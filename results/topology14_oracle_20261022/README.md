# 1〜14 CPUのトポロジー探索とアプローチ比較（2026-10-22）

全人数1〜14を扱い、Pなし・片側P・片側SMT・奇数E・層内LP-Eも含めて探索した。固定mask269種類を全測定し、層内/output切替を含む118,800候補では5手法×2seedを実際に動かした。独立8ブロックの確認での最速平均は **pthread P[2+2] E[2+2] LP0, 8→12, S, 1行**、**798.24 tok/s**。計3551測定（controlとwarmupを含む）を保存した。

## 前回から広げた範囲

前回480候補はP物理2個必須、E偶数などの制限があった。今回は全14論理CPUの全ての部分集合を、SMT・L2共有関係を保つ同値類へ写像した。14人の境界だけを追加した実験ではなく、層内人数1〜14を途中の性能低下でも打ち切らずに扱う。

|対象|元の組合せ|同値化後|実際の扱い|
|---|---|---|---|
|固定層内/output mask|2^14−1 = 16,383|269|全代表×2 backend×3ブロックを実測|
|層内⊆output の入れ子mask|3^14−2^14 = 4,766,585|14,850|全型を候補として定義し、適応探索|
|入れ子mask＋kernel設定|14,850×8|118,800|5手法×2seed×112候補を実測|

P物理コアごと、Eの共有L2群ごとの(l層内人数,o出力人数)を保持し、同種群と群内CPUの交換をまとめる。PとEとLP-Eは別型。2個のPと2個のE L2群の間で交換を許すが、SMTやL2の占有分割は潰さない。元の16,383固定mask全てが269代表へ写像されることをテストした。CPU rank順列を全探索したわけではなく、CPUの同種性も性能上は近似である。

kernel8設定はbackend(OpenMP/pthread)×層分配(static/dynamic16)×output1/4行。QKV/FFN融合、output dynamic32物理行、p_weight1を固定した。任意chunk、重み、バリア実装までの大域最適は対象外。[実験計画・空間とアルゴリズム](../../src/cpuprofiler/TOPOLOGY14.md)。

## 試した5アプローチ

全手法が共通の初期14測定で1〜14人を必ず一度ずつ見る。各手法の観測はaskした候補だけで、固定oracleの速度表をオンライン探索に渡していない。

- **random**: 同値類の一様探索。生CPU部分集合の一様探索とは分布が違う。
- **beam14**: 初期14点後、深さ1〜14の各段に7候補。上位3層内配置からCPUを1個追加し、output拡張とkernelも試す。前線が枯れたreplayでは再始動する。
- **hierarchical**: 56点まで固定配置を人数で層別探索し、有力層内配置のoutput拡張/kernelを後段で探索。早期の枝刈りに依存する。
- **model_counts**: P/E/LPの合計人数とkernelで逐次ridge推定。SMTの物理構造とL2占有分割を予測特徴から除く。
- **model**: SMT物理構造、L2群使用数/占有集中度、層内/output人数とkernelの相互作用を含む40特徴。両モデルはグローバル候補と最良4点のグラフ近傍から最大256点を提案し、LCBを使い、5回に1回一様探索する。

model_countsも候補表現とグラフはmodelと同じ。比較しているのは予測特徴からキャッシュ/SMTの情報を除く効果である。探索指標は真の速度の信頼区間ではない。推薦は観測済みの最良候補に限る。

## 今回の判断

実測2seedの平均確認gapが最小だった探索法は **model_counts**。ただしseed数は2つで、手法間の小差が確定したとはしない。L2/SMTを保持する同値化は空間の圧縮に役立ったが、予測特徴を増やすことまで今回の小予算で有利とは確認できなかった。人数中心の軽いモデルを初期候補とし、上位のCPU代表交換・独立再測定を組み合わせる方針が、この結果からの実用的な案となる。

固定oracleでは112照会の構造モデルは全探索に近かったが、全探索自体も評価ブロックの最良値からずれた。測定雑音とブロック間の順位変動があるため、探索点を増やすだけで確認性能が単調に改善するとは限らない。既知の採用候補も確認対象として保持し、新候補が確認で上回るまでは既知の候補を置き換えないのが妥当である。

## 同値化ヒューリスティックの点検と限界

P物理コア/EのL2群/LP-Eを交換した28配置を、代表と同じ条件で3ブロックずつ測った。交換による平均latency変化の絶対値は中央値4.67%、最大222.94%だった。これは同じ種類でも常に同速とは限らないことと、短い測定の雑音の両方を含む。温度・負荷・周波数snapshotだけでは原因を区別できない。

3ブロックの中央値で各対を要約すると、その絶対値の中央値は2.50%、最大は23.34%。算術平均の最大値は単発の極端な遅延の影響も受ける。外れ値は除外していない。セル中央値から2倍超/半分未満の測定はtiming_flags.csvに診断用として記録し、生値と平均を保持した。

[交換28対の結果](symmetry_checks.csv)には3ブロックの各差と探索的区間を保存した。同値化は探索費用を減らすための近似である。真の最適CPU番号やrank順列の保証はない。このため、各探索の上位1と固定oracle上位2は交換代表も独立確認に含めた。全同値類の全交換を調べたものではなく、残る代表やCPU順序は今後の検証点となる。

今回測った固定oracleは538候補であり、全118,800候補を総当たりしたとは主張しない。実測探索の112候補は全体の約0.094%だが、初期点・control・再確認の費用を含めて評価する必要がある。前回の粗いcontrol補正での失敗を踏まえ、今回は生値を目的にした。それでも一時的に速い点を選ぶ危険があり、独立確認を必須の評価手順とした。大型モデル・長文・別CPU・並行要求での最適性、任意chunkやバリア方式の最適性は未検証。
