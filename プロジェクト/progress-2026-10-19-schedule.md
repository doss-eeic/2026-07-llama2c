# 出力層メモリ最適化 計測結果（2026-10-19）：出力層の行の配り方（動的スケジュール）

方針: `プロジェクト/output-layer-memory-optimization.md`（以下「方針メモ」）3.1 節（A3 の帯域比の重み付け）、3.2 節
前回の計測結果: `プロジェクト/progress-2026-10-19-switch-c.md`（切替C）

## 1. まとめ

- 出力層を P コアと E コアにまたがって計算するとき（P4X）、行の配り方を変えて比べた。候補は (a) 固定の比、(b) 動的スケジュール、(c) 実行しながら比を調整する、の 3 つで、今回は **(b) を中心に単体ベンチマークで比較**した
- **基準機では効果は小さい**。fp32 で guided:1 が static（`run.c` の今の配り方）より −2.6%、dynamic:1・2 が −1.8〜2.0%。int8 では配り方による差はばらつきの範囲で見分けられなかった
- 待ち時間（一番遅いスレッドを待つ時間の割合）は 8.3% → 3.9% に減ったが、速さは 2.6% しか縮まなかった。出力層はメモリ帯域で律速しているので、P コアのスレッドが先に終わると残りの E コアのスレッドが帯域を多く使え、待ち時間がまるごと無駄になっていたわけではないため
- P コアだけ（P4_HT）では、dynamic:1 はブロックを取るコストの分 +4.8% 遅くなる。guided:1 は −0.7% で悪化しない
- **入れるなら guided:1**（どの構成でも static より悪くならず、`run.c` の変更は `schedule(guided)` を付けるだけ）。基準機ではほぼ得はないが、P と E の速さの差が大きいマシンで偏りを自動で吸収する保険になる
- (c) は、偏りを完全になくしても基準機での上限が 2〜3% 程度なので、基準機では効果が見込めない

## 2. 背景

切替C（`progress-2026-10-19-switch-c.md`）では、出力層の行を P4X の 8 スレッドに均等に配っている（`run.c` の `classifier_matmul()` は 64 行のブロックを `omp parallel for` の static で配る）。P コアと E コアは速さが違うので、均等に配ると遅いスレッドの終わりを全員が待つ。これを減らす配り方を比べた。

| 方式 | 内容 | 配る比の決め方 |
|---|---|---|
| (a) 固定の比 | スレッドごとの比を外から渡す | 事前に単体ベンチマークで測る |
| **(b) 動的スケジュール** | 手の空いたスレッドが次のブロックを取る（`schedule(dynamic, k)` / `schedule(guided, k)`） | 決めなくてよい |
| (c) 実行しながら比を調整する | 毎トークン各スレッドの所要時間を測り、担当を少しずつ変える | 実行中に自動で決まる |

どの方式でも 1 行の計算は 1 つのスレッドが同じループで行うので、出力は変わらない（今回の計測でも全条件で argmax が一致）。

### 事前の見込み

- 2026-10-15 の単体ベンチマーク（2MB ページ）では、帯域比での配分は fp32 で −2〜3.5%、int8 で差なしだった
- 単独で測った帯域を 4 スレッドで割ると、P コアは約 12 GB/s、E コアは約 11 GB/s（比 1.14）で、完全に揃えても短縮は最大 6% 程度の見込みだった

## 3. 実装（単体ベンチマーク、未コミット）

| ファイル | 変更 |

| `bench_memopt/bench_cls.c` | `--schedule range \| static \| dynamic:K \| guided:K` を追加。`range` は今までどおり各スレッドに連続した範囲（`--weights` の比）、それ以外は `run.c` の出力層と同じ 64 行のブロックを `omp for schedule(runtime)` で配る（K はブロックの数）。スレッドごとの所要時間・行数と、一番遅いスレッドを待つ時間の割合（`imbalance_pct` = 平均（最大 − 最小）÷ 平均 最大）を CSV に追加 |

| 項目 | 値 |

## 5. 結果

### 5.1 P4X（P コア + E コア、8 スレッド）

| 配り方 | fp32 (µs) | static との差 | 待つ割合 | int8 (µs) | static との差 | 待つ割合 |
|---|---|---|---|---|---|---|
| static（`run.c` の今の配り方） | 486.8 | ― | 8.3% | 80.2 | ― | 12.9% |
| range（均等） | 490.7 | +0.8% | 9.9% | 78.3 | −2.3% | 13.2% |
| range（帯域比） | 478.8 | −1.6% | 6.4% | 84.3 | +5.2% | 18.8% |
| dynamic:1 | 478.0 | −1.8% | 1.2% | 82.8 | +3.3% | 1.6% |
| dynamic:2 | 477.1 | −2.0% | 2.3% | 82.8 | +3.3% | 2.9% |
| dynamic:4 | 480.2 | −1.4% | 5.1% | 80.0 | −0.2% | 5.6% |
| dynamic:16 | 505.5 | +3.8% | 15.4% | 82.0 | +2.3% | 17.0% |
| **guided:1** | **474.1** | **−2.6%** | 3.9% | 79.3 | −1.0% | 3.3% |

- 待つ割合 = 一番遅いスレッドを待つ時間の割合（3 節）
- fp32 の dynamic:1 では、P コアのスレッドが 4400 行前後、E コアのスレッドが 3600 行前後を計算した（約 1.23 倍）。同時に動いているときの P と E の差は、単独で測った帯域の比（1.14）より大きい。帯域比での配分が弱かったのはこのためと考えられる
- dynamic:16 は 1 回に取るブロックが大きすぎて、最後に偏りが残る（待つ割合 15.4%）

### 5.2 P4_HT（P コアだけ、比較用）

| 配り方 | fp32 (µs) | static との差 | int8 (µs) | static との差 |
|---|---|---|---|---|
| static | 684.3 | ― | 172.0 ※ | ― |
| range（均等） | 682.9 | −0.2% | 158.8 ※ | −7.7% ※ |
| dynamic:1 | 717.2 | **+4.8%** | 154.8 | −10.0% ※ |
| dynamic:2 | 697.6 | +1.9% | 160.4 | −6.8% ※ |
| dynamic:4 | 692.6 | +1.2% | 155.2 | −9.8% ※ |
| dynamic:16 | 686.7 | +0.3% | 154.8 | −10.0% ※ |
| **guided:1** | **679.6** | **−0.7%** | 152.6 | −11.3% ※ |

- 同じ種類のコアだけのときは、もともと偏りがないので、dynamic:1 ではブロックを取るコストだけが乗って 4.8% 遅くなる。guided:1 はそのコストがほぼ出ない
- ※ int8 の static と range は、ばらつきで大きく出ている（6.2 節）。他の配り方との本当の差は ±3% 程度

### 5.3 待ち時間と速さの関係

fp32 の P4X で、guided:1 は待つ割合を 8.3% → 3.9% に減らしたが、速さは 2.6% しか縮まなかった。

出力層はメモリ帯域で律速している。P コアのスレッドが先に終わると、残りの E コアのスレッドが DRAM の帯域を多く使えるので、その分速く進む。そのため、待っている時間がまるごと無駄になっていたわけではなく、偏りを直しても速さは同じだけ縮まない。

## 6. ばらつき

### 6.1 全体

ばらつき（5 回の (最大 − 最小) ÷ 中央値）は、fp32 は全条件で 0.5〜2.0% と小さい。int8 は 1 回が約 80 µs（P4X）と短く、3.4〜13.7% と大きい。10% を超えたのは次の 3 条件。

| 条件 | ばらつき |
|---|---|
| P4X / int8 / dynamic:4 | 11.2% |
| P4_HT / int8 / range | 13.7% |
| P4_HT / int8 / static | 12.5% |

### 6.2 主な条件の 5 回の値（µs）

| 条件 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| P4X / fp32 / static | 486.8 | 481.7 | 490.8 | 489.3 | 485.2 |
| P4X / fp32 / dynamic:1 | 481.0 | 478.0 | 480.9 | 477.5 | 474.0 |
| P4X / fp32 / dynamic:2 | 480.1 | 476.0 | 481.0 | 477.1 | 473.3 |
| P4X / fp32 / guided:1 | 479.5 | 477.8 | 474.1 | 473.9 | 472.3 |
| P4X / int8 / static | 76.0 | 81.2 | 80.2 | 78.1 | 81.0 |
| P4X / int8 / dynamic:1 | 85.0 | 83.3 | 82.8 | 82.4 | 82.1 |
| P4X / int8 / guided:1 | 80.4 | 79.3 | 81.0 | 76.8 | 78.5 |
| P4_HT / int8 / static | 158.8 | 156.2 | **172.0** | **176.4** | **177.7** |
| P4_HT / int8 / range | 159.4 | 158.0 | 155.0 | **176.8** | 158.8 |

- **P4X の fp32 では、guided:1 と dynamic:1・2 が 5 回とも static より速い**。差は 2〜2.6% と小さいが、ばらつきを超えて安定している
- P4X の int8 は、どの配り方も 76〜86 µs の幅に収まり、差は見分けられない
- P4_HT の int8 の static は、3〜5 回目だけ 172〜178 µs と遅く、中央値（172.0 µs）が大きく出ている。正常な回（約 157 µs）で比べると、他の配り方との差は ±3% 程度。5.2 節の「−10%」前後は本当の差ではない

## 7. `run.c` での見込みと判断

| | 基準機での効果 | `run.c` での見込み |
|---|---|---|
| fp32 の出力層（P4X） | −2.6%（guided:1） | 出力層 507 µs → 約 12 µs 短縮（forward の約 1%） |
| int8-exact の出力層（P4X） | 差なし | 出力層 150 µs で、ほぼ変わらない |
| P コアだけの構成 | guided:1 なら悪化なし（dynamic:1 は +4.8%） | ― |

- 基準機では、単独で測った P と E の帯域の差が小さく、さらにメモリ帯域を分け合うので、偏りを直しても速さはあまり縮まらない
- 入れるとしたら guided:1。`run.c` の `classifier_matmul()` の `#pragma omp parallel for private(b)` に `schedule(guided)` を付けるだけで、出力は変わらない。fp32 の出力層（`matmul_nt` で `thread_share()` を使って均等に分けている）にも使う場合は、ブロック単位のループに書き換える必要がある
- P と E の速さの差が大きいマシンでは効果が大きくなりうるので、方針（任意のマシン）の観点では保険として意味がある
